# 验证记录

验证环境：Windows、Python 3.14、Node.js、本机已安装的 DeepSeek Harness 0.2.0-rc.2。验证仅使用专用私有任务仓库。

| 项目 | 结果与范围 |
|---|---|
| 桥接回归 | 41 项 Python 测试通过：所有者验证、完整审批 ID、跨 Issue 拒绝、过期、单会话队列、撤回、模型档位、默认路由变化、引导和精确轮次回传 |
| 宿主回归 | 9 项 Node 测试通过：一次允许、拒绝、幂等回执、会话／实例隔离、离线委托、超时、取消、认证 HTTP 及单会话模型接口 |
| 原生审批实机 | 通过：在新建隔离测试 Session 中使用 ask 策略，通过真实 GitHub 评论完成原生 ApprovalService 的 allowed-once 和 rejected；没有执行受保护操作 |
| 默认拒绝策略 | 通过：默认策略为 never 的隔离测试 Session 返回 rejected，远端桥接不能改变该策略 |
| 会话读取 | 通过：读取现有原会话目录、标题、可见消息和运行状态 |
| 原会话执行及回传 | 通过：真实任务在原 Session 生成 DSH_GITHUB_OK，匹配原 requestId 和 completed 轮次，并回传同一 Issue |
| 单会话与默认配置 | 通过：实际任务使用本机默认 provider／模型；执行后默认选择未变化 |
| 历史同步 | 通过：可见会话目录和历史发布到私有任务仓库，源码仓库不接收运行数据 |
| 完成提醒 | 已安装：独立 GitHub Actions 工作流；运行结果以 Actions 记录为准 |
| 源码与安装包 | 发布前执行源码凭据／个人路径审计、宿主资源一致性检查和 wheel 构建 |

GitHub Actions 配置 Python 3.11／3.14 与 Windows／Linux 矩阵。远端矩阵的结论以实际运行结果为准；本机没有代替验证其他操作系统。Android／iOS 独立 App、已有本机弹窗的接管和任意 DSH 版本兼容性不在本版本范围内。

后续实际使用修复验证：GitHub 请求超时原先会逃逸并终止监听，已用该调用位置的回归测试复现并修复；陈旧成功状态和死亡 PID 不再报告 ready。真实任务 Issue 6 的截图已发布到私有仓库并更新原回复。后台历史上传与留言轮询分离。监督进程已启动；自动重启路径未通过主动终止正在服务用户的监听器来验证。
